# 🚇 1호선 알리미

수도권 전철 **1호선** 열차가 지금 어디쯤 오는지, **집에서 몇 분에 나가면 되는지**를 한 화면에서 보여 주는 모바일 웹앱(PWA)입니다. **출발역 → 도착역**을 고르면 그 방향 열차 중 **도착역까지 실제로 가는 열차만** 골라 판정합니다. 기본 구간은 **두정 → 아산**입니다.

- 만든 목적: 두정동 집 → 두정역 도보 시간과 열차 도착 시간을 매번 머리로 계산하지 않기
- 실행: `index.html` 하나로 동작. 설치 없이 브라우저에서, 홈 화면에 추가하면 앱처럼
- 실데이터: 서울특별시 열린데이터광장 실시간 지하철 도착정보(OA-12764) + 열차 위치(OA-12601)
- 키가 없어도 **데모 모드**로 바로 화면과 판정 로직을 써 볼 수 있습니다.

## 1. 바로 실행하기

```bash
cd subway-1-radar
python3 -m http.server 8123
# 브라우저에서 http://localhost:8123 접속
```

`index.html`을 더블클릭해도 데모 모드는 동작하지만, 서비스 워커(PWA 오프라인)와 일부 브라우저의 `localStorage` 동작 때문에 **로컬 HTTP 서버**로 여는 것을 권장합니다.

휴대폰에서 보려면 같은 Wi-Fi에서 `http://<PC IP>:8123` 으로 접속한 뒤, Chrome 메뉴 → **홈 화면에 추가**.

## 3. 화면 구성

| 영역 | 내용 |
|---|---|
| 상단 바 | 현재 모드(데모/LIVE), 새로고침, 설정 |
| 출발 → 도착 | 두정 → 아산 기본. 각각 눌러 1호선 전체 역(연천~신창) 중 선택·검색, ⇄ 로 맞바꾸기. 전철 정면의 **행선표시기(LED 목적지판)** 자리에 표시 |
| 역 선택 시트 | 역마다 ☆/★ 버튼으로 즐겨찾기. 즐겨찾기한 역은 검색 중에도 **⭐ 즐겨찾기** 그룹으로 목록 맨 위에 고정 (`localStorage`) |
| 판정 카드 | 전철 정면의 **앞유리창** 안에 **지금 출발! / N분 뒤 출발 / 늦었어요** + **현재시각**·**열차출발** 두 가지 정보만 (v4에서 부제·칩 제거) |
| 이동 시간 | 1~30분 슬라이더(−/+ 버튼). 기본 10분, `localStorage`에 저장 |
| 준비하기 | 이동 시간 아래 🔔 토글. 켜 두면 **지금 출발!**이 되는 순간 승강장 열차 도착 멜로디(도·미·솔 상행 팡파르)·진동·화면 배너 |
| 미니 노선 트랙 | 전철 정면 **하단 코발트 띠**(레드/실버 띠·전조등·범퍼) 위에 출발역 앞뒤 역과 열차 위치를 실시간 배치 |
| 열차 목록 | **승강장 LED 전광판** 톤(딥 슬레이트 프레임 + 앰버/에메랄드/레드 LED). **최대 4대**까지, 왼쪽에 도착까지 남은 시간, 행선지, **급행/일반/ITX/막차** 배지, 추정 근거, 도착역까지 못 가는 열차 제외 안내. 행 오른쪽은 두 줄 — 위에 그 열차가 **출발역을 떠나는 시각**(`15:42 출발` 배지), 아래에 **도착역에 닿는 시각**(`16:01 도착`, v19) |
| 상태 카드 | 30초 자동 갱신 on/off, 마지막 갱신 시각, 오류 안내 |

**v5 비주얼**: 상단 3개 영역(출발→도착 · 판정 카드 · 열차 위치)이 1호선 전철을 정면에서 본 한 덩어리 실루엣(둥근 지붕 → 전면 행선표시기 → 큰 앞유리창 → 코발트 하단 띠 + 레드/실버 띠 + 양쪽 전조등 + 범퍼)으로 이어지고, 그 아래 `다가오는 열차`는 역사 승강장 LED 전광판처럼 보입니다. 밝은 하늘·코발트 배경 위에 전철이 서 있는 구성은 라이트/다크 모두 유지됩니다.

### 출발 판정 규칙

`이동 시간(walk)`과 `열차 도착까지 남은 시간(eta)`을 비교합니다. 승강장 도착 후 최소 1분(`BOARD_MARGIN`)을 남깁니다.

| 조건 | 표시 |
|---|---|
| `eta - walk` 가 1.5분 이하 (아직 탑승 가능) | **지금 출발!** (여유 N분) |
| `eta - walk` 가 1.5분 초과 | **N분 뒤 출발** — `N = ceil(eta - walk - 1)` |
| `eta - walk` 가 −0.5분 미만 | **늦음** — 다음 열차 기준으로 안내 |

열차 목록의 각 카드 왼쪽은 같은 규칙으로 매긴 남은 시간(색 띠·배지 색으로 상태 구분)을 보여 줍니다. 오른쪽은 두 줄입니다(v19).

| 줄 | 내용 | 계산 |
|---|---|---|
| 위 (배지) | 그 열차가 **출발역을 떠나는 시각** `HH:MM 출발` | `지금 + 남은 시간` |
| 아래 (보조 라벨) | **도착역 도착 예정 시각** `HH:MM 도착` | `출발 시각 + 구간 소요시간`(stations.js, 급행·ITX는 0.85배) |

예) 두정 → 아산(구간 9분), 20:25 출발 예정인 열차는 20:34 도착으로 표시됩니다. 급행·ITX는 같은 구간을 0.85배(약 8분)로 계산합니다.

목록은 가까운 순서로 **최대 4대**입니다.

### 도착역까지 가는 열차만 (종착역 필터)

`stations.js`의 노선 그래프(경부본선·장항선·경인선·서동탄지선)에서 **출발역 → 열차 종착역** 최단 경로를 구해, 그 경로에 **도착역이 들어 있는 열차만** 남깁니다. 진행 방향(상·하행)도 같은 그래프의 첫 구간으로 정합니다.

| 선택 | 표시 | 제외 |
|---|---|---|
| 두정 → 아산 | 신창·온양온천·배방·탕정·아산행 | **천안·봉명·쌍용행** (아산 전에 종착) |
| 두정 → 서울역 | 서울역·시청·청량리·광운대·연천행 | **구로·수원·병점·인천행** (서울역까지 안 감) |
| 아산 → 서울역 | 서울역 이북행 | 천안·수원·인천행 |

걸러진 열차가 있으면 목록 아래에 `도착역까지 못 가는 열차 N대 제외됨 (천안·봉명행)`처럼 작게 표시합니다. 종착역을 알 수 없는 열차는 지우지 않고 `행선지 미상`으로 남깁니다. 급행·ITX는 정차역이 달라 별도 안내 문구를 함께 보여 줍니다.

### 준비하기 · 출발 벨소리

1. 이동 시간 아래 **🔔 준비하기**를 누릅니다(이때 Web Audio 컨텍스트를 열어 브라우저 자동재생 정책을 풀어 두고, 바뀐 멜로디의 앞소절(솔-도-미-솔)을 바로 들려줍니다).
2. 판정이 **지금 출발!**로 바뀌는 순간, Web Audio로 합성한 **승강장 열차 도착 팡파르**(솔-도-미-솔이 두 번 올라갔다 길게 끝나는 3.1초 멜로디)가 3.4초 간격으로 반복되고 `navigator.vibrate` 진동·화면 상단 알람 배너가 뜹니다.
3. **알람 끄기**를 누르면 소리·진동이 즉시 멈추고(예약해 둔 음까지 끊음) 준비 상태도 꺼집니다. 켜 둔 동안에는 `navigator.wakeLock`으로 화면 잠금을 막아 봅니다(미지원 브라우저는 조용히 넘어감).
4. 설정 시트나 준비 중의 **미리듣기**로 멜로디 전체를 먼저 확인할 수 있습니다.

#### 알람 소리 설계 (v18)

브라스(톱니파 두 겹 + 한 옥타브 아래 사각파, 저역통과 엔벨로프)로 팡파르를, 사인 배음 4개로 차임을 합성합니다. 외부 음원 파일이 없어 지하 승강장에서도 네트워크 없이 바로 울립니다.

소리 경로: `음 → 재생 게인 → DynamicsCompressorNode → GainNode(2.2배) → WaveShaper(tanh 소프트 클립) → 스피커`

- **컴프레서**(threshold −13 dB · ratio 6)로 음이 겹쳐도 찢어지지 않게 눌러 주고, 그 뒤에서 **마스터 게인으로 2.2배** 더 키워 폰 스피커에서도 크게 들리게 했습니다.
- **소프트 클립**(tanh)이 최대 0.96을 넘지 않게 막아, 크게 키워도 디지털 클리핑(찌그러짐)이 없습니다.
- Chrome 실측(OfflineAudioContext 렌더): 이전 딩동 벨 **최대 −8.7 dBFS · RMS −29.7 dBFS** → v18 팡파르 **최대 −0.1 dBFS · RMS −7.7 dBFS**(체감 음량 약 22 dB 상승, 클리핑 0샘플).

브라우저는 화면이 꺼지거나 탭이 백그라운드로 내려가면 소리를 막을 수 있습니다. 그래서 준비 중에는 `화면을 켜 두면 출발 시각에 벨소리가 울려요` 안내를 띄웁니다.

## 4. 실데이터 연결

### 4-1. 서울시 인증키 발급 (약 3분)

1. <https://data.seoul.go.kr> 로그인
2. **서울시 지하철 실시간 도착정보** 검색 → `OA-12764` → **활용신청** (자동 승인)
3. **서울시 지하철 실시간 열차 위치정보** `OA-12601` 도 같이 신청하면 위치 보정까지 동작
4. 마이페이지 → 오픈API → 인증키 발급현황에서 **일반 인증키** 복사 (32자리)

### 4-2. 앱에 넣기

앱 우측 상단 ⚙ → **데이터 소스**

| 방법 | 설명 | 주의 |
|---|---|---|
| **데모 모드** | 키 없이 시뮬레이션 | – |
| **API 키 직접** | 키만 붙여넣기 | `http://localhost` 처럼 http 페이지에서는 실제로 동작합니다(확인 완료). 다만 서울시 API가 `http://` 라서 **https 페이지(GitHub Pages·PWA 설치)** 에서는 Mixed Content로 막히고, 브라우저·정책에 따라 CORS로도 막힙니다 |
| **프록시 URL (권장)** | 아래 Worker 주소 입력 | https·CORS 모두 해결, 키를 앱에 저장하지 않아도 됨 |

키는 브라우저 `localStorage`에만 저장되고 어디로도 전송되지 않습니다(설정에서 지우면 삭제).

### 4-3. Cloudflare Worker 프록시 (무료)

`worker.js` 파일이 그대로 Worker 코드입니다.

```bash
npm i -g wrangler
wrangler login
wrangler init subway-proxy          # 이 폴더의 worker.js 를 src/index.js 로 넣기
wrangler secret put SEOUL_API_KEY   # 서울시 인증키 입력
wrangler deploy
```

배포되면 `https://subway-proxy.<계정>.workers.dev` 주소가 나옵니다. 앱 ⚙ → 데이터 소스 **프록시 URL** 에 넣고 저장하세요.

- 앱은 `GET {프록시}/realtimeStationArrival/0/30/두정` 형태로 호출합니다. (로컬 테스트용으로는 파이썬 http.server 같은 간단한 프록시도 같은 경로만 맞추면 됩니다.)
- Worker는 이 경로만 허용하고(화이트리스트), 15초 캐시를 붙여 호출 한도를 아낍니다.
- 키를 Worker 환경변수에 두면 앱에는 키가 남지 않습니다.
- Node/파이썬 등 다른 서버로 프록시를 만들어도 경로만 같으면 됩니다.

## 5. 코레일 구간 추정 로직 (이 앱의 핵심)

서울시 도착정보 API는 서울교통공사 구간에서는 `barvlDt`(도착까지 초)를 정확히 주지만, **두정·천안·평택 같은 코레일 구간에서는 `barvlDt`가 비거나 0으로 오고**, 대신 다음처럼 옵니다.

```json
{ "arvlMsg2": "[2]번째 전역 (성환)", "arvlMsg3": "성환", "barvlDt": "", "arvlCd": "99" }
```

그래서 `stations.js`에 **역 순서 + 인접 역 평균 소요시간(분)** 을 내장하고, 아래 순서로 도착 시각을 계산합니다.

1. `arvlCd` 가 진입(0)·도착(1)·출발(2) → 이미 역에 있음 (각 20초/4초/0초)
2. `barvlDt` 가 유효(1~5400초) → 그 값에서 **데이터 생성 시각(`recptnDt`) 지연**을 뺌
3. `arvlMsg2/3` 파싱
   - `"(N)번째 전역 (역명)"` → 그 역에서 기준역까지 **구간 시간 합** − 0.5구간(이미 출발한 평균 위치)
   - `"N분 후 (역명)"` → N분
   - `"당역 도착"`, `"전역 출발"` 등 → 해당 상태
4. 그래도 없으면 **실시간 열차 위치**(`realtimePosition`)의 `statnNm` + `trainSttus`(진입/도착/출발)로 보정
5. 급행/ITX 는 구간 시간 합에 **0.85배** 보정

예) 두정역 기준 `[2]번째 전역 (성환)` → 성환→직산 4분 + 직산→두정 3분 = 7분 − 약 1분 ≈ **6분 뒤 도착**

### 실제 응답에서 확인한 형식 (2026-11 두정역)

| 필드 | 도착정보(realtimeStationArrival) | 위치정보(realtimePosition) |
|---|---|---|
| `updnLine` | **`"상행"` / `"하행"` (문자열)** | `"0"` / `"1"` (문자열) |
| `barvlDt` | 코레일 구간은 **`"0"`** (초 값 없음) | – |
| `arvlMsg2` | `"[4]번째 전역 (아산)"`, `"[6]번째 전역 (송탄)"` | – |
| `arvlMsg3` | `"아산"`, `"송탄"` (역명만) | – |
| `trainLineNm` | `"천안행 - 직산방면 (막차)"` → 막차 판정에도 사용 | – |
| `trainSttus` | – | `"0"` 진입 / `"1"` 도착 / `"2"`, `"3"` 출발 |
| `directAt` | – | `"1"` 이면 급행 |

`updnLine` 이 두 API에서 서로 다른 표기라 `app.js` 의 `dirOf()` 에서 `"0"/"상행"` → 상행, `"1"/"하행"` → 하행으로 정규화합니다. `barvlDt` 가 `"0"` 이면 값이 없는 것으로 보고 3번(메시지)·4번(위치) 경로로 넘어갑니다. 막차는 `lstcarAt="1"` 또는 `trainLineNm` 의 `(막차)` 로 판정합니다.

장항선 **탕정역**처럼 최근 개통·개명된 역도 역 목록에 포함되어 있습니다. 목록에 없는 역명이 메시지로 오면 그 열차만 실시간 위치 보정으로 넘어갑니다.

### 한계

- 구간 소요시간은 평시 기준 **근사값**입니다(역간 2~6분). 실제와 ±1~2분 차이가 날 수 있습니다.
- 급행은 통과역이 있어 0.85배 근사만 적용합니다(정차역 표 기반이 아님).
- 1호선은 구로에서 인천지선과 경부선 남부로 갈라지고 서동탄지선이 있습니다. 방향과 경로는 그래프에서 계산하지만, 미니 트랙은 출발역 기준 앞뒤 3~5역만 그립니다.
- API의 `updnLine`(0 상행/1 하행)이 역에 따라 반대여도, 종착역이 확인되면 그래프로 방향을 다시 계산합니다. 종착역을 모르는 열차만 API 방향을 씁니다.
- 서울시 API 자체가 일시 중단되면 "열차 정보가 없어요"로 표시됩니다. 운행 시간대가 아니어도 같습니다. (심야에는 상행 1대처럼 열차가 아주 적을 수 있습니다.)
- 인증키는 소스·README·manifest 어디에도 저장하지 않습니다. 앱 ⚙에서 입력한 값만 브라우저 `localStorage`에 남고, 프록시 모드에서는 키를 Worker 환경변수에 두어 앱이 키를 몰라도 됩니다.
- 막차 여부는 API의 `lstcarAt` 값을 그대로 씁니다.

## 7. 데모 모드가 하는 일

- 두정 → 아산 기본 구간의 열차 6대가 36분 주기로 실제처럼 다가옵니다. 도착역 전에 끝나는 열차(천안·봉명행)도 섞여 있어 **필터가 일하는 모습**을 바로 볼 수 있습니다.

- 화면 상단 `데모` 배지로 항상 구분되며, 실데이터로 바뀌면 `LIVE`로 표시됩니다.
